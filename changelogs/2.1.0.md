# CustomDeathMessages 2.1.0 Developer Changelog

Changes since `2.0.3`. Every fix below was reproduced and then verified on real Paper servers (1.8.8, 1.12.2,
1.16.4, 1.16.5, 1.20.4, 1.20.6, 1.21.4, 1.21.11 and 26.1.2) with bot players. Spigot itself was not
run; its chat code path was exercised through Paper 1.8.8 - 1.16.4 (which use the same path) and by forcing it on
Paper 1.20.4 and 1.21.11.

## Version compatibility

- **1.8 - 1.12.0:** head drops called `SkullMeta#setOwningPlayer` (via SkullCreator), which only exists since
  1.12.1. The `NoSuchMethodError` aborted the whole death handler, so every death that rolled a head drop (50% by
  default) lost its custom message and PvP messages. Heads now use a version-safe helper and can never break the
  death message.
- **26.x:** NBTEditor failed to initialize. The handler had already cleared the vanilla message, so PvP deaths
  with `%kill-weapon%` showed no death message at all. NBTEditor is gone.
- **1.16+ item hovers:** 1.16 - 1.20.4 nested the whole item inside its own tag (names and enchantments
  missing) and 1.20.5+ sent a bare item. Paper 1.16.5+ now uses Paper's own `ItemStack#asHoverEvent()`; other
  servers use the tooltip format of their era.
- **Paper 1.21.x+:** the `PlayerLoginEvent` listener made Paper disable the re-configuration APIs for the whole
  server. Update notifications now use `PlayerJoinEvent`.
- **1.21.11+:** game rule names changed; the `showDeathMessages` check now uses the typed `GameRule` API.
- Hex colors (`&#RRGGBB`) are approximated with the nearest legacy color before 1.16 instead of rendering the
  color of the last hex digit.
- The plugin now compiles against the Paper 1.16.5 API (was spigot-api 26.1), so the compiler flags APIs that
  older servers lack; newer APIs are accessed defensively.

## Death attribution

- The killer is resolved from `Player#getLastDamageCause()`, the damage that actually killed the player, instead
  of a 60-second map filled by a MONITOR listener plus `Player#getKiller()`. Fixes:
  - cancelled lethal hits (protection plugins) and hits survived with a totem being used for a later death;
  - players who merely hit the victim getting credit (and "You killed ...") for fall, lava and mob deaths, which
    also turned such deaths into melee PvP messages when their hand was empty;
  - dying to your own arrow/firework/trident/ender pearl counting as a PvP kill by yourself;
  - players with a custom name using the custom-named mob messages.
- Thorns, dragon breath and sonic boom messages are reachable again (the attacking entity's list always won).
- The stored damage cause is cleared on respawn, so deaths without a damage event (sourceless damage on 1.8,
  `setHealth(0)`) are not blamed on the previous life's killer.
- Death causes map to lists through `MessagePaths`; any `<entity-or-cause>-messages` list is picked up
  automatically. Added trader llama, parched, breeze wind charge, creaking and zombie nautilus. Unknown types are
  logged once instead of twice per death.

## Death message delivery

- Paper 1.16.5+: the message is set as an Adventure component on the event. The server handles the gamerule,
  console, vanish plugins, Discord bridges and cancellation.
- Spigot / older Paper: the plain message is set at NORMAL; at MONITOR, if no other plugin changed it and the death
  was not cancelled, the hoverable version is broadcast (honoring `showDeathMessages`).
- Previously hover mode broadcast the message itself at NORMAL priority, ignoring the gamerule, vanish plugins,
  cancellation and later changes, and called EssentialsDiscord/DiscordSRV directly (bypassing their formatting,
  vanish checks and markdown escaping). The Discord integrations and their compile dependencies are removed;
  bridges now read the event's message.
- The template's color before `%kill-weapon%` is kept on the weapon, and the text after it continues in the
  template's style.
- Lightning and PvP messages run at MONITOR and only for deaths that were not cancelled.
- Heads are added to the event drops (graves/death chests can capture them) and use the victim's own profile (no
  Mojang lookup).

## Placeholders

- PlaceholderAPI and color codes are applied to the template before player-controlled values are inserted, so
  item names and nicknames can no longer inject color codes or placeholders. Values are inserted in one pass.
- Placeholders without a value resolve to an empty string instead of being printed literally.
- `%kill-weapon%` works for mob killers (a skeleton's bow).
- PlaceholderAPI is called directly through an isolated bridge instead of reflection.

## Config and commands

- A config that fails to parse no longer replaces the active config: `/cdm reload` keeps the previous config and
  reports the line and column. Previously the plugin silently fell back to the default messages and the next
  `/cdm add/remove/set` saved them over the user's file.
- Command edits re-read `config.yml` first (hand edits are kept) and refuse to save while it is broken.
- A broken config at startup disables the plugin with a short message instead of a stack trace cascade.
- `/deathmessage` works (it was only declared in `plugin.yml` and silently did nothing); commands are no longer
  declared in `plugin.yml`.
- Empty lists mean "vanilla message", blank messages mean "no message"; the last message of a list can be removed.
- `/cdm list` shows raw text with `&` codes; `/cdm set number` validates ranges; `config-version` is no longer
  settable; confirmations echo the new value; path completions refresh after reloads.
- `message-cooldown` only limits the global message (it also skipped heads, lightning and PvP messages).
- Update checks run at startup and every 6 hours with timeouts (previously an HTTP request per login, before the
  permission check), compare versions numerically, and the hard-coded username greeting is removed.
- New installs default to no lightning and no head drops. Head drops never worked before 2.0.2 (the wrong key was
  read), so the old 0.5 default unexpectedly started dropping heads on half of all deaths. Existing configs keep
  their values. `config-version` is now 4.
- Config documentation rewritten; typos fixed.

## Removed / changed API

- `CustomPlayerDeathEvent` is removed (it was an internal round trip; use `PlayerDeathEvent`).

## Build

- ACF, bStats and BoostedYAML are relocated under `org.spartandevs.customdeathmessages.libs`; ACF is pinned to an
  exact snapshot build; NBTEditor and SkullCreator are removed; annotation-only classes are no longer shaded.
